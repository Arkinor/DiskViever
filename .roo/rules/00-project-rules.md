# Правила работы над проектом DiskViever

Эти правила обязательны для любого агента, который продолжает работу над проектом.

## 1. Документация обязательна

- В корне проекта есть файл [`доработки.md`](../доработки.md) — это **единственный источник правды**
  о состоянии проекта: что сделано, что в работе, что запланировано.
- Перед началом работы — прочитать `доработки.md`.
- После каждого завершённого шага — обновить в нём статус (`[ ]` → `[x]`), добавить заметки
  о принятых решениях и о том, что осталось.
- Формат записей: коротко, по делу, без «воды». Любой другой агент должен суметь продолжить
  работу с того места, где остановился предыдущий.

## 2. Тесты и скрипты

- **Не создавать тестовые/отладочные скрипты** (`test_*.py`, `check_*.py`, `tmp_*.py`, `scratch_*.py`
  и подобные) без прямой просьбы пользователя.
- **Не запускать тесты, линтеры и проверки** без прямой просьбы пользователя.
- Проверка работоспособности — только запуск самого приложения (`python main.py`), и только
  если пользователь об этом попросил или это явно требуется для демонстрации результата.
- Временные файлы, созданные в процессе работы, удалять сразу после использования.

## 3. Код

- Python 3.11, Tkinter + Matplotlib. Никаких новых тяжёлых зависимостей без необходимости.
- Стиль существующего кода: `snake_case`, комментарии и подписи интерфейса — на русском.
- Цвета и шрифты брать только из [`theme.py`](../theme.py). Не хардкодить hex-значения в новых модулях.
- Новый функционал размещать в отдельных модулях (`smartclean/`), не раздувать `main.py`.
- Существующий функционал визуализатора не ломать: новая функциональность живёт в отдельной вкладке.
- Любая операция удаления файлов должна:
  - быть подтверждена пользователем;
  - по умолчанию использовать корзину (`send2trash`), а не безвозвратное удаление;
  - не трогать системные каталоги, помеченные как `report_only`.

## 4. Безопасность

- Запрещено удалять что-либо из `C:\Windows\System32`, `C:\Windows\WinSxS`, `C:\Program Files`
  и пользовательских каталогов документов без явного выбора пользователя.
- Правила очистки описываются декларативно в [`smartclean/rules.py`](../smartclean/rules.py)
  с обязательным уровнем риска (`safe` / `caution` / `danger`).
