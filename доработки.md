> Единственный источник правды о состоянии проекта.

## 0. Правила

Полные правила — в [`.roo/rules/00-project-rules.md`](.roo/rules/00-project-rules.md). Кратко:

- Не создавать тестовые скрипты без просьбы пользователя.
- Не запускать тесты/линтеры/проверки без просьбы пользователя.
- Новый функционал — в отдельных модулях (`smartclean/`), не раздувать `main.py`.
- Цвета и шрифты — только из [`theme.py`](theme.py).
- Удаление — только с подтверждением и по умолчанию в корзину.

### Известные ограничения / что улучшить

- [ ] Сканирование системных правил требует прав администратора: сейчас такие элементы
      показываются, но удаление может падать — ошибки попадают в отчёт. Можно добавить
      индикатор «нужен админ» в таблице и попытку `ShellExecuteW(runas)`.
- [ ] Нет настройки исключений (whitelist пользователя). Планируется файл
      `~/.diskvieuver/exclude.json` и кнопка «Исключить».
- [ ] Нет предпросмотра содержимого папки внутри вкладки (только «Открыть»).
- [ ] Дубликаты файлов не ищутся (отдельная будущая фича).
- [ ] `Windows.old` / WinSxS / точки восстановления — только отчёт.
- [ ] Автообновление визуализатора следит только за `mtime` каталога, не за размерами
      файлов внутри (изменение размера файла без изменения состава папки не заметно).
- [ ] Не реализован прогресс-бар с процентами для сканера очистки (сейчас индeterminate).

## 2. Спецификация «Умная очистка» (реализовано)

### 2.1 Правила (`rules.py`)

`CleanRule` — frozen dataclass:
`id, name, description, risk, category, paths, patterns, min_age_days,
contents_only, report_only, requires_admin`.

`iter_targets()` разворачивает `%ENV%`, `~` и glob-шаблоны, отдаёт существующие пути.

Категории правил:

| Категория | Примеры | Риск |
|-----------|---------|------|
| Временные файлы | `%TEMP%`, `C:\Windows\Temp` | safe / caution |
| Системный кэш | INetCache, WebCache, thumbcache, D3DSCache | safe / caution |
| Кэш видеодрайверов | NVIDIA DXCache/GLCache, AMD, Intel | safe |
| Windows Update | SoftwareDistribution\Download, DeliveryOptimization, Prefetch | safe / caution |
| Логи и отчёты | WER, CrashDumps, Minidump, Logs, Panther, FontCache | safe / caution |
| Кэш браузеров | Chrome, Edge, Brave, Yandex, Opera, Firefox | safe |
| Кэш приложений | Discord, Slack, Teams, Spotify | safe |
| Кэш разработчика | pip, npm, NuGet | safe |
| Игровые кэши | Steam shadercache | safe |
| Загрузки | старые EXE/MSI/ISO в Downloads (>45 дней) | caution |
| Корзина | `C:\$Recycle.Bin` | caution |
| Системные файлы | Windows.old, WinSxS\Backup, Installer, pagefile/hiberfil | danger, `report_only` |

### 2.2 Поиск остатков программ

1. `installed.collect_installed_programs()` собирает программы:
   реестр Uninstall (3 ветки), Steam (все библиотеки), Epic (манифесты), GOG (реестр),
   ярлыки Start Menu, каталоги `Program Files` / `Games` / `SteamLibrary` / `Epic Games` /
   `GOG Games` на **всех** локальных дисках.
2. `classifier.build_program_index()` строит нормализованные имена и токены.
3. `orphans.find_orphans()` проходит верхний уровень `AppData\Local`, `Roaming`,
   `LocalLow`, `ProgramData`, `Documents`, `Saved Games` и помечает папки, которые:
   - не системные (белый список `SYSTEM_FOLDER_NAMES`);
   - не сопоставились с программами;
   - старше 30 дней;
   - больше 5 МБ.
   Такие элементы — `Risk.CAUTION`, не выбираются автоматически.

### 2.3 Модель данных

```python
CleanableItem(rule_id, name, path, size, risk, category, description,
              can_delete, contents_only, is_orphan, note, selected, extra)
ScanResult(items, errors, duration, rules_checked, installed_programs)
```

### 2.4 Удаление (`actions.delete_items`)

- Пропускает `can_delete=False`, несуществующие пути, корни дисков и критичные каталоги.
- `contents_only` → удаляются только дети каталога.
- Корзина: `send2trash` → fallback WinAPI `SHFileOperationW` (FOF_ALLOWUNDO).
  Если корзина недоступна — **исключение**, безвозвратного удаления не происходит.
- Журнал: `~/.diskvieuver/cleanup_log.jsonl` (ts, path, size, rule, recycle_bin).
- Возвращает `DeleteOutcome(deleted, freed, failed, skipped)`.

### 2.5 UI (`ui_tab.SmartCleanerTab`)

- Шапка: заголовок, сводка (`Найдено / Безопасно / Выбрано / Остатки`), кнопки
  (`Анализ`, `Стоп`, `Безопасное`, `Снять выбор`, `Удалить выбранное`, `Открыть`,
  `Отчёт CSV`), галочка «В корзину», фильтр, прогресс-бар, статус, легенда рисков.
- Таблица: `Treeview` с категориями-родителями, чекбокс `☐/☑` в первой колонке,
  размер, риск; цвета по риску; `report_only` — серые, без чекбокса.
- Клик по чекбоксу — переключение; `Space` — переключение; двойной клик — открыть папку;
  ПКМ — меню (открыть, копировать путь, выбрать).
- Панель «Подробности»: имя, размер, риск, категория, описание, примечание, путь.
- Сканирование и удаление — в фоновых потоках; статус обновляется throttle-ом 120 мс.

## 4. Как проверять вручную (по просьбе пользователя)

```bash
pip install -r requirements.txt
python main.py
```

1. Вкладка «Визуализатор» → клик по диску: должен появиться спиннер и текст сканирования.
2. Создать/удалить файл в открытой папке → через ~4 секунды данные обновятся
   (или нажать `F5`).
3. Вкладка «Умная очистка» → «Анализ» → дождаться завершения, проверить категории,
   выбрать «Безопасное», убедиться, что элементы уходят в корзину.
4. Проверить, что опасные (`Windows.old`, `WinSxS`) не имеют чекбокса.

  тысяч файлов). Причина была в основном потоке Tk: 14 полных перерисовок холста подряд
  при анимации открытия; полная сортировка всего списка и построение словаря имён на
